# 终端功能验收边界

更新：2026-10-10（审核修订：增加 A0、整链用例要求、遗漏场景与性能观测项）。本文件是当前验收标准。既有固定采样次数、连续若干天及整日等待不再充当完成判据；时间只在数据新鲜度、延迟或指定业务事件本身要求时使用。性能测量用于定位，实际卡顿必须处理。

## 证据规则

每个案例记录：代码 SHA/发布版本、环境、数据时间和版本、前置账户/市场状态、真实界面操作、预期结果、实际结果、request/order/fill/run ID（公开材料脱敏）、截图或 trace、后端副作用核对、失败原因及负责工作包。

状态限定为：未实施、代码完成、隔离环境通过、生产验证通过、外部阻塞、被门控阻断。CI 绿灯、服务 active、接口 200、截图或零成交回测均不能单独证明业务闭环。

每个 ID 必须对应一条 W0 底座中的可运行整链用例（真实 FastAPI、worker、SQLite、Nautilus，不拦截订单/账户接口），或一条带证据模板的人工步骤；二者都没有的 ID 不能标为通过。合成输入产生的证据标为“合成”，真实市场案例单独登记。

## 功能完成条件

| ID | 真实用户操作 | 必须观察到的结果 |
|---|---|---|
| A0 平台可交易性 | 打开每个平台当日市场 | 至少一个合约 `parse_status=parsed`、有模型概率和策略评估；否则该平台 A2–A10 一律记“被门控阻断”，不能记通过 |
| A1 市场与天气 | 打开终端，切 Kalshi/Poly US、市场日、档位，再刷新 | 站点/日期/规则/行情/天气一致；旧请求不覆盖新选择；缺数据局部提示，界面继续可用 |
| A2 Paper 买卖 | 选模拟账户，查看预检，提交买单，再卖出 | UI 回执与原生订单、成交、现金/预留、持仓对应；限价和成交价分列；刷新后状态一致 |
| A3 挂单与撤单 | 提交可保留挂单，撤单，重复点击或模拟超时后恢复 | 只有一次意图；确认撤单才释放预留；未知态先查询原订单；部分成交及剩余数量正确 |
| A4 策略触发 | 从界面选择 S1/S2/S3，运行已冻结场景或开启 Paper 策略 | 预警→触发→候选→拒绝/订单→成交可追溯；关闭自动执行仍显示信号；部分成交与每日限次正确 |
| A5 风险和停止 | 设置额度/白名单，制造越限，再停止策略 | 越限被拒且原因明确；停止后不新开策略仓位；是否保留或撤销已有单由明确控件决定，不能隐式混淆 |
| A6 天气研究 | 选 KNYC 时段与策略，运行并打开一个触发及一个失败日 | 显示输入覆盖、数据时基、触发、概率与标签；训练/校准无未来泄漏；可复现且不伪装交易收益 |
| A7 交易回测 | 导入/选择已有或平台历史数据，选策略和成交模型运行 | 覆盖不足明确拒绝或降级；至少一个有成交的完整案例核对订单→持仓→费用→结算；同输入重跑一致 |
| A8 结算 | 回放已结算实际合约；另记录自然发生的在线结算 | 按该版本官方结果清理订单、更新现金与仓位；重复结算无二次入账；离线及在线证据分列 |
| A9 恢复 | 隔离环境中断连接/worker，在未决请求、部分成交及持仓状态恢复 | 原生账目和状态保留，无重复订单/成交；旧数据明确标识；正常交互可恢复 |
| A10 Live | 在账户、白名单和风险参数确定后完成授权范围内的真实订单流程 | 平台原生订单/成交、撤单及本地账目匹配；重启后对账；工具要求人工提交的环节由用户完成；本轮不执行 |
| A11 页面可用性 | 在真实规模数据下切换、缩放、开票、撤单；后台同时回测/归档 | 操作有明确反馈、图表/历史不阻塞票据；错误局部显示；记录卡顿触发条件和 profile，不靠不断加次数通过 |
| A12 第二城 | 下一阶段从同一入口选择另一个真实城市并走 A1/A4/A6/A7 | 无 KNYC 站点/时区/规则串用；独立模型/标签；不复制整套引擎或终端 |

双平台分别记录 A0–A10 的适用结果。真实规则歧义导致 no-trade 可证明门控正确，同时交易闭环仍未通过；两种结论必须同时保留。

## 必测场景

除上表外，以下场景必须各有用例：IOC 零成交后的重试上限（策略 v3：最多 1 次）；S1 一腿成交另一腿未成交（残腿不补单）；费用舍入与预留释放；同一合约重复结算不二次入账；worker 在提交请求后、收到回执前重启；Poly US 未知订单的人工确认解除；全局停止与一键撤单；额度修改即时生效于服务端。

## 性能观测

A11 记录：Paper/回测 feed 游标与最新 seq 的差值（后台积压）、界面操作到回执的耗时、触发卡顿的数据规模和操作。积压持续增长或回执超出可交易时效视为失败，不设固定采样次数。

## 环境分层

现有 mock Playwright 测试保留，用于交互和失败分支。增加真实 FastAPI、worker、独立数据库及真实 Nautilus 的整链案例，浏览器从可见入口驱动，不拦截内部订单/账户 API 来制造成功。平台边界可在隔离环境注入故障，但须写明替代边界。

生产复验只覆盖本次受影响的用户流程。自然市场没有触发时先用冻结输入验证行为，在线案例单独待验；不可通过绕过规则或修改生产数据制造交易机会。

## 失败处理与停止条件

同一失败只登记一个问题，写清“预期/实际/证据/根因假设/修复工作包”。修复后重跑失败案例及受影响邻接流程；没有代码、数据、环境变化，不重复全量验收。权限、样本或市场状态阻塞时记录解除条件，继续独立任务，禁止通过重建账户、放松门禁或清除账目获得通过。

一个功能工作包包含相关模块、测试、文档和修复后再提交一个 PR。严重生产事故可单独 hotfix。合并遵守分支保护，不能由 agent 自称独立审核或绕过审批。
