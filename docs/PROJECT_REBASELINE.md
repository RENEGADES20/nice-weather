# 改进计划（W0–W6）

2026-10-10 独立审核后修订，替代同日 P0–P5 序列（原文见 git 历史 `97117cb`）。缺陷编号 D*/R* 见 [审核报告](AUDIT_2026-10-10.md)；工程参考、历史数据路线和天气市场文献已移至 [RESEARCH_INDEX §7](RESEARCH_INDEX.md)。

## 排序原则

先修让核心功能跑不通的阻断，再补研究与回测。原计划把 Kalshi 可交易性、实盘额度和实盘策略放到最后，会延续“验收通过但人工用不了”。每个工作包一个 PR（含调用方、后端、界面、测试、文档和相关修复），且必须在 W0 底座上新增至少一条不 mock 订单/账户接口的整链用例。

## 历史数据

优先级：已有本地/R2/研究资产 → 官方历史下载（Kalshi 实时与归档层按 cutoff 分页去重；Poly US Price History / Time & Sales） → 可核验第三方。仅当具体策略需要且外部历史缺失时，另提最小采集方案（范围、容量、费用）。缺真实 `received_at` 时标为 source-time 研究，不补造。

## 协作与验证

- 一个集成负责人维护功能目标、接口和证据；仅独立任务并行，明确文件边界。
- 实现者的完成声明不能代替审查；资金、订单、迁移类改动单独复核。
- 同一失败无新变化时再现，停止重试，转根因分析；权限/样本阻塞记录解除条件后继续其他工作。
- 不新建常驻编排平台、消息总线、长期行情采集服务或多城插件框架。
